Monoprice Monolith HTP-1

Control4 driver for the HTP-1 AV processor, over IP.

Driver 104 · requires Control4 OS 3.x · HTP-1 firmware 1.13.x or 2.1.x

What this driver does

Presents the HTP-1 to Control4 as a receiver, with feedback in both directions. Commands from a remote, keypad or touchscreen reach the unit, and changes made on the unit's front panel, its handheld remote or its own web UI come back to Control4 without being asked for.

  • Power on, standby and sleep
  • Input selection across all 20 inputs
  • Discrete volume and hold-to-ramp
  • Mute
  • Loudness on, off and toggle, from the room's own control
  • Dirac, night mode, dialog and bass enhancement, lip sync
  • Dirac filter slot selection, by the unit's own slot names
  • Running the macros the unit already stores, by the owner's own names
  • Listening mode across all seven upmixers
  • Programming commands for Dirac Live, night mode, dialog and bass enhancement, lip sync delay, the Dirac filter slot, and the unit's stored macros
  • Read-only status: formats, sample rates, video
  • Driver events for programming
  • Unattended reconnection

The driver holds one WebSocket to the unit and is entirely event-driven — it never polls. An idle connection carries no traffic beyond a keepalive every 30 seconds.

Installing

  1. Add the driver to the room.
  2. On the Connections tab, set the unit's IP address on the network connection. A static address or a DHCP reservation is strongly recommended.
  3. Bind your sources to the HDMI inputs, the display to an HDMI output, and the amplifiers to the audio output.
  4. Bind the room to the Room Selection end-point. Without this the room's volume and mute buttons do not reach the driver at all.
The driver claims nothing on its own. Unlike most receiver-class drivers, this one does not take over a room's audio and video endpoints when you add it. Every binding is yours to make deliberately.

Connection Status, System Software Version and Serial Number filling in together is the proof that the connection opened and the unit's state was read. If Connection Status stays Not connected, check the IP address first — the driver retries on its own and needs no prompting once the address is right.

Dirac Filter The unit's own six slot names, refreshed automatically Selects the active Dirac filter slot. Each entry reads <slot number> - <name>, using the same number as the DIRAC_SLOT variable, so a slot the owner never named still appears as, e.g., 2 - Slot 2 rather than being left out. Macro The macros this unit stores, under the names its owner gave them Chooses which stored macro the Run Selected Macro action runs. Only slots that actually hold something appear — a macro slot the owner named but never filled is left out, because selecting it could only do nothing. A macro the owner never named appears under its slot key, e.g. cmdcustom3. Choosing an entry only selects it; nothing is sent to the unit until you run it. The list refreshes on its own when a macro is stored, renamed or emptied on the unit.
The driver replays macros; it cannot write them. A macro on this unit is a list of settings changes saved in one of its fixed slots (cmda–cmdd, preset1–preset4, cmdcustom1–cmdcustom16), and running one means sending those same changes back — which is exactly what the unit's own web interface does. Creating, editing, renaming and deleting macros belong to the unit's own UI, and this driver deliberately offers none of them. Whatever is in a slot is the owner's own stored intent, so the driver sends it as it stands.

Actions

Composer's Actions tab. Output appears in the Lua tab with this driver selected.

ActionWhat it does
Refresh From Device Re-reads the unit's full state. The driver keeps itself current on its own; use this if you suspect it has drifted.
Print Input Labels Lists every input the unit reported: the Control4 connection, the unit's own label for it, and whether the unit considers it visible. Inputs Control4 cannot select are listed too and marked as such. Use it to decide what to rename your connections to.
Run Selected Macro Runs the macro chosen in the Macro property above, by sending the settings it stores. Use it to try a macro from Composer before wiring it into programming. If the slot turns out to be empty, nothing is sent and the Lua tab says so.
Print Driver State Dumps the driver's current view of the unit. Useful when reporting a problem.
The driver cannot rename Control4's inputs for you. The receiver proxy provides no way for a driver to set an input's name, so connection names come from this driver's own declarations. Print Input Labels tells you what the unit calls each input; renaming the connections in Composer is a manual step.

Commands

Programming commands, available anywhere a device command can be chosen in a Control4 program -- not the Actions tab above, which is for one-off use from Composer itself.

CommandParameterWhat it does
Set DiracMode: Off / On / Bypass Sets Dirac Live processing.
Set Night ModeMode: Off / Auto / On Sets night mode, which compresses dynamic range for quiet-hours listening.
Set Dialog EnhanceLevel: 0–6 Sets the dialog enhancement level.
Set Bass EnhanceMode: Off / On Sets bass enhancement.
Toggle Bass Enhance— Flips bass enhancement from whatever it currently is.
Set Lip Sync DelayDelay: 0–340 ms Sets the lip sync delay, both the calibration value and the currently selected input's own delay -- matching what the unit's own web client does, so the unit's display and the driver agree.
Set Dirac SlotSlot: 0–5 Selects the active Dirac filter slot by number, for programming that knows the slot it wants rather than its name. The Dirac Filter property above is the way to choose one by name from Composer.
Run MacroMacro: text Runs one of the unit's stored macros, sending the settings it holds. Type either the name the owner gave the macro on the unit (Movie Night) or its slot key (cmda, preset1, cmdcustom3). The slot key is the durable choice: renaming the macro on the unit does not break programming written against it.
An empty or unknown macro does nothing at all. A name that matches no macro, or a slot with nothing stored in it, earns a line on the Lua tab (with Debug Mode on) and no message to the unit — never a half-run macro, and never an empty one the unit would reject. The macro list in the Macro property is the reliable way to see what a name has to match.
An out-of-range or unrecognised value is refused, not passed through. A Level outside 0–6, a Delay outside 0–340, or a Mode the unit does not have earns a log line on the Lua tab (with Debug Mode on) and no write at all -- the unit is left exactly where it was.

An unknown value reads empty, not Off or false. Before the driver has read the unit — and briefly after a driver reload — these are genuinely unknown rather than false, and the driver will not invent an answer. CONNECTED is the one variable that is always meaningful, so check it before trusting the rest.

The unit reports its own placeholders when there is no signal: ----- for resolution, -- for HDR. Those are the unit's words, passed through unchanged.
The room's Loudness button is one-way. The receiver proxy accepts loudness commands but defines no way for a driver to report loudness back — its only state notifications are for volume, mute and surround mode. So the room's control shows what it last set, and a change made on the unit's own front panel will not move it. The LOUDNESS variable above is always correct, so use that wherever the real state matters.

Events

EventFires when
ConnectedThe driver has read the unit's state and is live.
DisconnectedThe connection to the unit is lost.
Powered OnThe unit turns on.
Powered OffThe unit turns off.
Input ChangedThe selected input changes, from any source.
Surround Mode ChangedThe unit's reported surround mode changes.
Read state on Connected, not on Powered On. The transition events fire only on a real change. After a driver reload or a controller restart, they do not fire for state that was already true — so a unit that was already on does not produce a Powered On. That is deliberate: a controller reboot must not trigger programming written for someone actually switching the system on. If your programming needs the current state at startup, read the variables when Connected fires.

Troubleshooting

Connection Status stays "Not connected"

Check the IP address on the Connections tab, and that the unit answers on port 80 from the controller's network. The driver retries on its own with a widening delay, so once the address is right it recovers without being restarted. Set Debug Mode to On for 15 Minutes and watch the Lua tab for the reason.

The room's volume or mute buttons do nothing

The room must be bound to the driver's Room Selection end-point. That binding is what routes a room's volume and mute to the driver at all.

Volume moves in the wrong steps

The unit works in whole decibels and Control4 in percent, so a percentage change smaller than one decibel lands on the same value. Volume in decibels is the truth; the percentage is derived from it. Check Maximum Volume too — a cap rescales the whole range.

The system turns off when I only wanted the room off

Set Power Off Action to Do Nothing.

Reporting a problem

Set Debug Mode to On for 15 Minutes, reproduce the problem, then run Print Driver State and copy the Lua tab. Note the System Software Version — behaviour differs between 1.13.x and 2.1.x.

This driver talks to the unit over its local WebSocket interface and needs no cloud account, no Monoprice login and no internet access.
