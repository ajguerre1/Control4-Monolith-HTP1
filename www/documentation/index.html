Monoprice Monolith HTP-1

Control4 driver for the HTP-1 AV processor, over IP.

Driver 107 · requires Control4 OS 3.x · HTP-1 firmware 1.13.x or 2.1.x

What this driver does

Presents the HTP-1 to Control4 as a receiver, with feedback in both directions. Commands from a remote, keypad or touchscreen reach the unit, and changes made on the unit's front panel, its handheld remote or its own web UI come back to Control4 without being asked for.

  • Power on, standby and sleep
  • Input selection across all 20 inputs
  • Discrete volume and hold-to-ramp
  • Mute
  • Loudness on, off and toggle, from the room's own control
  • Dirac, night mode, dialog and bass enhancement, lip sync
  • Dirac filter slot selection, by the unit's own slot names
  • Running the macros the unit already stores, by the owner's own names
  • Listening mode across all seven upmixers
  • Programming commands for Dirac Live, night mode, dialog and bass enhancement, lip sync delay, the Dirac filter slot, and the unit's stored macros
  • Read-only status: formats, sample rates, video
  • Driver events for programming
  • Unattended reconnection

The driver holds one WebSocket to the unit and is entirely event-driven — it never polls. An idle connection carries no traffic beyond a keepalive every 30 seconds.

Installing

  1. Add the driver to the room.
  2. On the Connections tab, set the unit's IP address on the network connection. A static address or a DHCP reservation is strongly recommended.
  3. Bind your sources to the HDMI inputs, the display to an HDMI output, and the amplifiers to the audio output.
  4. Bind the room to the Room Selection end-point. Without this the room's volume and mute buttons do not reach the driver at all.
The driver claims nothing on its own. Unlike most receiver-class drivers, this one does not take over a room's audio and video endpoints when you add it. Every binding is yours to make deliberately.

Connection Status, System Software Version and Serial Number filling in together is the proof that the connection opened and the unit's state was read. If Connection Status stays Not connected, check the IP address first — the driver retries on its own and needs no prompting once the address is right.

Updating to a newer version

  1. Copy the new Monolith.HTP1.c4z over the old one in your Drivers folder. The file name never changes between releases, which is what makes Composer update this driver in place rather than add a second one.
  2. Driver › Add or Update Driver or Agent…, and pick the file.
Composer caches a driver by its version number, not by the file. If you replace the .c4z without the version changing, Composer keeps using the copy it already has in memory and your new file is ignored — silently, with nothing in any log to say so. Every release here bumps the version, so this only bites when building your own.
The device icon is set when the device is added, and never updated afterwards. Control4 writes the icon onto the project item at the moment you add the device, and updating a driver does not rewrite it. So a release that changes the icon will not change what you see in System Design, no matter how many times you update. Only removing the device from the project and adding it again picks up a new icon — at the cost of redoing its bindings. Nothing else about an update needs this; it is specific to the icon.

Dirac Filter The unit's own six slot names, refreshed automatically Selects the active Dirac filter slot. Each entry reads <slot number> - <name>, using the same number as the DIRAC_SLOT variable, so a slot the owner never named still appears as, e.g., 2 - Slot 2 rather than being left out. The list and the current selection update on their own whenever the unit reports a change, from any source.

The selection follows the slot, not the name: renaming the slot the unit is currently using moves that entry's label and leaves it selected. The six slots are fixed and cannot be deleted, so this property never has to fall back to a different filter — and in the one case where it cannot say which is active, it shows nothing selected rather than naming a filter that is not the one running.
Macro The macros this unit stores, under the names its owner gave them Chooses which stored macro the Run Selected Macro action runs. Only slots that actually hold something appear — a macro slot the owner named but never filled is left out, because selecting it could only do nothing. A macro the owner never named appears under its slot key, e.g. cmdcustom3. Choosing an entry only selects it; nothing is sent to the unit until you run it. The list refreshes on its own when a macro is stored, renamed, emptied or deleted on the unit.

The list always begins with (none), and that entry does nothing. It is there so that deleting the selected macro on the unit never promotes a different macro into its place — the selection falls to (none) and Run Selected Macro does nothing until you pick again. If the unit ends up storing no macros at all, (none) is the whole list.

Your selection follows the macro, not the name it is shown under: renaming the macro you selected — or renaming or adding any other — leaves your choice intact, so programming built on Run Selected Macro keeps working across a rename on the unit. Deleting or emptying the macro you chose clears the selection. So does renaming it while the driver is not running to see the change — on the next connection the driver can no longer tell which macro you meant, so it falls back to (none) rather than guess at a different one.

One consequence worth knowing: a macro the owner names literally (none) is listed under its slot key instead, e.g. preset1, so that it stays selectable and cannot be confused with the empty entry.
The driver replays macros; it cannot write them. A macro on this unit is a list of settings changes saved in one of its fixed slots (cmda–cmdd, preset1–preset4, cmdcustom1–cmdcustom16), and running one means sending those same changes back — which is exactly what the unit's own web interface does. Creating, editing, renaming and deleting macros belong to the unit's own UI, and this driver deliberately offers none of them. Whatever is in a slot is the owner's own stored intent, and the driver passes it through without second-guessing which settings a macro is allowed to touch.
Only replace entries are replayed. A macro slot holds a list of change entries, and this driver sends back the replace ones — a path and the value to put there. It skips every other kind. A test entry is a condition the unit evaluates, not a change, and sending it as a change would apply it; an add would arrive as a change to something that does not exist yet, which the unit rejects outright, taking the rest of the macro with it. A remove cannot be expressed at all: this driver's write path sends values, and a delete is the absence of one.

Macros saved from the unit's own UI are normally all replace, so this usually costs nothing. When it does not, the driver says so in the Director log — ran 3 of 5 stored entries — whatever Debug Mode is set to, because a macro that ran in part is not something you would otherwise notice.

Actions

Composer's Actions tab. Output appears in the Lua tab with this driver selected.

ActionWhat it does
Refresh From Device Re-reads the unit's full state. The driver keeps itself current on its own; use this if you suspect it has drifted.
Print Input Labels Lists every input the unit reported: the Control4 connection, the unit's own label for it, and whether the unit considers it visible. Inputs Control4 cannot select are listed too and marked as such. Use it to decide what to rename your connections to.
Run Selected Macro Runs the macro chosen in the Macro property above, by sending the settings it stores. Use it to try a macro from Composer before wiring it into programming. With (none) selected — which is what you get before you have chosen anything, and after the macro you had chosen was deleted on the unit — nothing is sent and the Lua tab says so. Same if the slot turns out to be empty.
Print Driver State Dumps the driver's current view of the unit. Useful when reporting a problem.
The driver cannot rename Control4's inputs for you. The receiver proxy provides no way for a driver to set an input's name, so connection names come from this driver's own declarations. Print Input Labels tells you what the unit calls each input; renaming the connections in Composer is a manual step.

Commands

Programming commands, available anywhere a device command can be chosen in a Control4 program -- not the Actions tab above, which is for one-off use from Composer itself.

CommandParameterWhat it does
Set Dirac ProcessingMode: Off / On / Bypass Turns Dirac Live processing on, off, or into bypass. Which calibrated filter it runs is Set Dirac Slot below, or the Dirac Filter property.
Set Night ModeMode: Off / Auto / On Sets night mode, which compresses dynamic range for quiet-hours listening.
Set Dialog EnhanceLevel: 0–6 Sets the dialog enhancement level.
Set Bass EnhanceMode: Off / On Sets bass enhancement.
Toggle Bass Enhance— Flips bass enhancement from whatever it currently is.
Set Lip Sync DelayDelay: 0–340 ms Sets the lip sync delay, both the calibration value and the currently selected input's own delay -- matching what the unit's own web client does, so the unit's display and the driver agree.
Set Dirac SlotSlot: 0–5 Selects the active Dirac filter slot by number, for programming that knows the slot it wants rather than its name. The Dirac Filter property above is the way to choose one by name from Composer.
Run MacroMacro: text Runs one of the unit's stored macros, sending the settings it holds. Type either the name the owner gave the macro on the unit (Movie Night) or its slot key (cmda, preset1, cmdcustom3). The slot key is the durable choice: renaming the macro on the unit does not break programming written against it.
An empty or unknown macro does nothing at all. A name that matches no macro, or a slot with nothing stored in it, earns a line on the Lua tab (with Debug Mode on) and no message to the unit at all — nothing partial is sent in either case, and never an empty message the unit would reject. The macro list in the Macro property is the reliable way to see what a name has to match. A slot that does hold entries can still run in part, if some of them are kinds this driver cannot replay — see Only replace entries are replayed above.
An out-of-range or unrecognised value is refused, not passed through. A Level outside 0–6, a Delay outside 0–340, or a Mode the unit does not have earns a log line on the Lua tab (with Debug Mode on) and no write at all -- the unit is left exactly where it was.

An unknown value reads empty, not Off or false. Before the driver has read the unit — and briefly after a driver reload — these are genuinely unknown rather than false, and the driver will not invent an answer. CONNECTED is the one variable that is always meaningful, so check it before trusting the rest.

The unit reports its own placeholders when there is no signal: ----- for resolution, -- for HDR. Those are the unit's words, passed through unchanged.
The room's Loudness button is one-way. The receiver proxy accepts loudness commands but defines no way for a driver to report loudness back — its only state notifications are for volume, mute and surround mode. So the room's control shows what it last set, and a change made on the unit's own front panel will not move it. The LOUDNESS variable above is always correct, so use that wherever the real state matters.

Events

EventFires when
ConnectedThe driver has read the unit's state and is live.
DisconnectedThe connection to the unit is lost.
Powered OnThe unit turns on.
Powered OffThe unit turns off.
Input ChangedThe selected input changes, from any source.
Surround Mode ChangedThe unit's reported surround mode changes.
Read state on Connected, not on Powered On. The transition events fire only on a real change. After a driver reload or a controller restart, they do not fire for state that was already true — so a unit that was already on does not produce a Powered On. That is deliberate: a controller reboot must not trigger programming written for someone actually switching the system on. If your programming needs the current state at startup, read the variables when Connected fires.

Troubleshooting

Connection Status stays "Not connected"

Check the IP address on the Connections tab, and that the unit answers on port 80 from the controller's network. The driver retries on its own with a widening delay, so once the address is right it recovers without being restarted. Set Debug Mode to On for 15 Minutes and watch the Lua tab for the reason.

The room's volume or mute buttons do nothing

The room must be bound to the driver's Room Selection end-point. That binding is what routes a room's volume and mute to the driver at all.

Volume moves in the wrong steps

The unit works in whole decibels and Control4 in percent, so a percentage change smaller than one decibel lands on the same value. Volume in decibels is the truth; the percentage is derived from it. Check Maximum Volume too — a cap rescales the whole range.

The system turns off when I only wanted the room off

Set Power Off Action to Do Nothing.

Reporting a problem

Set Debug Mode to On for 15 Minutes, reproduce the problem, then run Print Driver State and copy the Lua tab. Note the System Software Version — behaviour differs between 1.13.x and 2.1.x.

Changelog

The number in brackets is the driver version Composer shows in the Driver Version property. Every release installs over the one before it: the file name never changes, so Composer updates in place rather than adding a second driver.

1.0.7  (driver 107)

  • The icon is now the Monolith brand mark, on its own dark tile so it reads against both Composer's light tree and a dark touchscreen. The wordmark is deliberately left out — it is illegible below about 90px.
  • If 1.0.6's icon never appeared for you, this is why, and it was not a fault in the driver: Control4 writes a device's icon onto the project item when the device is added, and never rewrites it when a driver is updated. Remove the device and add it again to pick up the new icon. See Updating to a newer version above.

1.0.6  (driver 106)

  • The driver has its own icon in Composer's System Design tree, instead of the stock receiver image.
  • An icon set for Navigators and touchscreens ships too, at the five sizes Control4 uses, but it will not render for this driver and that is not a fault in it: a receiver-class device does not get its own Navigator tile — it is an AV path and volume device rather than a selectable source — and the Control4 component that drives a receiver does not read icon declarations at all. The files are inert, correct, and kept for the day this driver grows a device type that does show one. The Composer tree icon above is the one that renders.
  • This changelog, and the version above it, are now checked against the driver's declared version on every test run — they had drifted once.

1.0.5  (driver 105)

  • Fixed: deleting the selected macro on the unit promoted a different macro into its place, so Run Selected Macro quietly began running something else. The list now always carries a (none) entry and the selection falls there.
  • Fixed: renaming the selected macro on the unit lost the selection. It now follows the macro rather than the name, so programming keeps working across a rename.
  • The selection re-anchors on reconnect, so a macro slot edited while the driver was offline cannot inherit your selection.
  • A macro named literally (none) is listed under its slot key, so it stays selectable.

  • Macro — pick one of the macros the unit stores, and run it from an action or from programming.
  • This documentation tab.
  • Renamed: Set Dirac became Set Dirac Processing. The old name was a strict prefix of Set Dirac Slot, which invites picking the wrong one in a program. Neither name had shipped, so no existing programming was affected.

1.0.3  (driver 103)

  • Fixed: all three Composer actions were dead and said nothing about it. Composer's Actions tab sends the literal LUA_ACTION with the action name in the parameters, not the action's own command; the driver found no handler and returned in silence. An unrecognised action now prints instead of failing quietly.
